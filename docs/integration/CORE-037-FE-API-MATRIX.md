## Concrete cross-source findings

- F36 `service.ts` returns `mode:'unavailable'` for every operation in real mode; `runtimeClient.ts` only calls `/api/auth/me`. No medical HTTP request or live FE/BE integration exists.
- F36 `models.ts` uses `string` IDs, a bare `MedicalCase[]` and `Incident[]`, singular `incidentId`, `position3d` coordinates, medications array and completion notes. C006 and B035 use numeric IDs, paged lists, `incidentIds[]`, opaque `position3d`, one medication instruction string and an empty completion body.
- B035 `MedicalService.java` rejects nonempty Groom task materialization and requires `ActorResolver`, `IncidentLink` and `GroomTaskScope` adapters. The branch documentation says they are not production wired. B026 `Core026Controller.java` has no review endpoint. These are implementation blockers, even where C006 declares a path.
- F36 `pages.tsx` has loading, empty, retry and post-save refresh behavior in mock mode. These states need regression tests after a real adapter exists. The case page currently defaults missing recovery to `NOT_RECOVERED`; the adapter must distinguish unknown from a persisted clinical outcome.
- F36 `runtime.tsx` gates routes by actor role, but `runtimeClient.ts` receives no token from its route wrapper. CORE-008/CORE-007 auth integration and Backend authorization remain required.
